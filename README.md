# 《验火》· 古籍断案解谜（一案 · 三卷 · 十典）

你是**提刑司的验官**。火宅一案，一具焦尸。**火，是烧死了他，还是替他遮了别的死法？**

你不能靠一条公式破案——验口灰、剃髻验钉、验血入地、验隐形伤、辨伪伤、辨火之自燃、
核油账、验烛时、查呈报……**各出一门手艺，散在十部古书里**。
每翻对一卷，才敢下一个断语；而**下一个断语，又会决定上一条还要不要验**。十典合拢，案子才唯一地合上。

> 别人做古籍是"贴皮"，这一作让玩家**在断案的过程里，真的翻对了"该看哪本书的哪一条"**。

- **游戏类型**：单机 · 断案推理 · 文化科普（文游）
- **技术形态**：单文件 HTML（内嵌 JS/CSS），离线运行，零依赖、零外部素材
- **目标平台**：任意现代浏览器（双击即玩）；手机自适应
- **单局时长**：约 20–35 分钟

## 玩法循环

**读案由 → 翻书问典 → 案牍推演 → 结案唯一。**

1. **读案由**：一桩火案，取自《折狱龟鉴 · 庄遵疑哭》——哭声「惧而不哀」，火宅必有隐情。
2. **翻书问典**：每一「验目」都要求你先选对**该翻哪部古书、哪一条**；选错书＝**误检**，得出错事实、损时日一日。选对则弹出「原文卡」——**原文 + 白话 + 原理**，科普在此交付。
3. **案牍推演**：事实之间**互为条件**（先验得「口鼻无灰」，才需验「囟门钉」；验得「钉入」，才追凶器）。案牍板随取证进度逐条点亮。
4. **结案七槽**：取证足够后，把事实填进**七个结案槽**（焚尸先后 / 致命之因 / 火起之因 / 凶器 / 主谋 / 内应 / 引律），填齐才可落判；未填齐时点「落判」，会明确列出还差哪一槽、缺哪条事实。
5. **验官不设死路**：误检只损「时日」、不判死，可随时回溯改检。

> 谜题答案不作剧透。卡关请回想：**这一步该翻哪部书？**

## 为什么是"解谜"而非"算数"

前一版（`立样`）被一句话点破：「这不是算数吗？它算解谜吗？」——其空缺都可由**一条定式直接算出**。

本作不同：**没有任何一条结论能单靠一本书算出**。
第 2 目要用第 1 目的结果决定要不要做；第 3 目（钉之制）的结论又反过来限定凶手身份；
十二条小规则（一验目一约束）互相咬合，**只有一处满足全部约束的结案**——这是**约束满足 / 推断**，不是代数。

## 迭代记录

- **v1 · 校勘（顶针联珠）**——废弃：答案可由邻居一字直接读出，退化为机械补字。
- **v2 · 立样（营造材分）**——降为赛后扩展：空缺可由单条定式直接算出，属连续代数。
- **v3 · 验火（一案多典）**——现行：结论只能由「选对典籍 ＋ 叠加约束」得出。
- **v3.1 · 结案与存档**——修正落判判定的回调误用（`SLOTS.every(slotCorrect)` 把槽对象当 id 传入，
  `slotById` 恒为 null 后继抛错，导致七槽填满后点「落判」静默无反应）；新增进度自动保存、重置进度、
  误检递进提示（3 次标书 / 5 次标条目）与「已得条目不重复计误检」。
